# v0.1.0-alpha.5

オープンだった Issue #9〜#17 をまとめて修正します（PR #18）。旧ドラフト PR #8（DSH 0.2 系の peer 範囲と HMR 再導入拒否への追従）の内容も含みます。

## 重要な変更

- **必要な Node.js は 22.18.0 以上になりました**（`engines.node: >=22.18.0`）。公開されている `dsh` は Node.js 22.18.0 で入った `import.meta.main` が真のときだけ起動するため、それより古い Node.js（20 系や 22.14.0 など）では、`dsh` が何も出力せずに終了コード 0 で終了します。
- **更新候補の peer 範囲は 0.2 系列の内側に限ります。** 各代替範囲が下限と上限を持ち、範囲全体が `>=0.2.1-alpha.2 <0.3.0-0` の内側にあるリリースだけを更新候補にします。`*`、`>=0`、`^0`、下限のない範囲、`<0.3.0`（`-0` なし）、`0.2.x`、`workspace:` などは導入しません。このプラグイン自身の peer は `>=0.2.1-alpha.2 <0.3.0-0` です。

## 修正した Issue

- #9 設定画面の文言を英語・日本語・中国語の辞書に移し、DSH の言語設定に合わせて表示します。
- #10 更新候補の peer 範囲を 0.2 系列の内側に限定しました（上記）。
- #11 「保護設定を作成して接続」が押せないとき、理由をボタンのそばに表示します。
- #12 管理操作は TCP 接続元・Host がともに loopback で、転送元ヘッダがない場合だけ許可します。公開 Tunnel 経由では `status` 以外の操作を拒否します。
- #13 Cloudflare 組織の AMR 設定が代替認証を許す、または判断できない場合は公開を止めます。
- #14 connector token を形式とアカウント・Tunnel の一致で検証してから保存し、失敗時は既存の token と動作中の接続を維持します。
- #15 OAuth の拒否・期限切れ・交換失敗を停止後も保持し、状態 API に認可 URL や秘密を含めません。
- #16 過去の接続確認と現在の接続状態を分けて表示し、確認後の HTTP 5xx で確認済みを消さないようにしました。
- #17 変更操作の途中でも停止を Host に送り、「停止中」を表示します。

## 導入

```sh
dsh plugin --profile web add github:Aero123421/dsh-cf#v0.1.0-alpha.5
```

ソースから導入するため、リリース添付ファイルは不要です。`0.1.0-alpha.4` の更新確認は peer を完全一致の版番号として読むため、範囲を書いたこの版は alpha.4 の画面からは導入できません。DSH のプラグイン設定か上の `dsh plugin` で一度入れてください。
