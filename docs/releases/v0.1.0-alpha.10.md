# v0.1.0-alpha.10

開発プレビューです。v0.1.0-alpha.9 以降の安全性と設定画面の修正を含みます。

## 変更内容

- 引き継いだ cloudflared の停止を確認できないとき、未解決のプロセス記録をプロファイルの再起動・プラグイン再読込を越えて保持します。安全を確認するまで新しい connector は起動しません（[#29](https://github.com/Aero123421/dsh-cf/pull/29)）。
- 設定画面で、プレースホルダーを含むアカウント名が二重展開される問題と、Cloudflare が HTTP 400 で拒否したトークン入力の案内を修正しました。smoke 検査では npm の警告が JSON 出力に混入しなくなりました（[#30](https://github.com/Aero123421/dsh-cf/pull/30)）。
- npm latest を DSH 互換性検査に追加し、npm 12 の dist-tags 出力にも対応しました（[#31](https://github.com/Aero123421/dsh-cf/pull/31)）。

## 導入・更新

```sh
dsh plugin --profile web add -w 'github:Aero123421/dsh-cf#v0.1.0-alpha.10'
```

DSH を再起動しブラウザを再読み込みしてください。公開設定と connector token は保持します。管理用 API トークンは保存しないため、設定変更時に再入力します。

**pnpm 10 の使用を推奨します。** pnpm 12 では公開から間もない依存の minimum release age エラーによりプロファイルの node_modules が空になり、そのプロファイルの全プラグインが読み込めなくなる場合があります。復旧には pnpm 10 で `dsh plugin --profile <profile> install` を実行してください。pnpm 11 では既存 store との不一致で導入が止まる場合があります。

## 検証と制限

Linux x64、Node.js 22、pnpm 10 の隔離環境で DSH 0.2.1-rc.5（当時の latest/next）と 0.2.2-alpha.2 の公式 Host を使い、パックしたプラグインの導入、trustedHosts の保存と再読込、launch exchange、HTTP/RPC/WebSocket、ローカル RSA/JWT と公開側の管理拒否を確認しました。alpha.2 は Node 24.9 以上を要求するため、Node 22 での結果は正式な対応を意味しません。公開 app-boot の peer 判定は npm 10 と npm 12 で確認しました。CI は Node 24 の runtime smoke を含みます。

Cloudflare API・Access と connector はローカル fixture を使用しています。実 Cloudflare アカウント・実公開 Tunnel・実 IdP、macOS、Windows、Electron、Safari/iPadOS は今回未検証です。以前の検証の詳細は[互換性記録](../dsh-compatibility-2026-10-29.md)を参照してください。

## リリース資産

ソースから導入します。tarball を付ける場合は以下で作成し、GitHub Release に添付します。

```sh
npm ci
mkdir -p dist
npm pack --pack-destination dist
( cd dist && sha256sum dsh-cf-*.tgz > SHA256SUMS )
```

`sha256sum -c SHA256SUMS` で照合できます。npm 12 がロック済み GitHub tarball を `EALLOWREMOTE` で拒否する環境では、明示的に `npm ci --allow-remote=all` としてください。
