# v0.1.0-alpha.7

接続が正常なときの使い方を保ち、設定変更の失敗、DSH再起動、複数端末、プラグイン更新からの復旧を改善しました。

## 修正と改善

- 入力・既存構成との一致・DSH・接続ソフトを検証してから接続を置き換えます。変更できないホスト名やメールを送った場合、稼働中の接続と再接続に必要な確認記録を保持します。設定済みの変更できない項目は画面でも編集不可にしました。
- Hostの起動世代と連番を照合します。設定画面を開いたままDSHを再起動しても状態が再同期され、古いHostの応答やエラーが新しい表示を上書きしません。起動世代を持つ古い画面からの変更要求も拒否します。
- WebSocketを接続ごとに集計します。端末を1つ閉じても、別端末の正常な接続を未確認へ戻しません。
- 言語辞書と所有する言語登録を解除時に片付け、再読込後は新しい辞書を使います。他プラグインの言語登録は解除しません。
- 更新候補の`engines.dsh`を優先し、なければDSHのpeerDependenciesを確認します。旧版の更新画面から導入できるよう、この版は従来のpeer宣言も維持しています。
- 変更のない更新結果の保存を止め、完了後の監視を減らしました。新たに確認できた更新結果は、次の一覧取得が失敗しても復元できるよう先に保存します。
- 狭い設定領域に「設定を広く表示」を追加しました。プラグインだけを広いダイアログで開き、Tab移動・Escape・フォーカス復帰・編集中の入力保持に対応します。
- 再起動後の再接続操作、APIトークン作成と必要権限へのリンク、日本語・英語・中国語のエラー案内、DSHのtheme tokenを整えました。
- 不明な書き込みに読み取り専用の確認を追加しました。識別マーカー・対象ホスト・IDを照合して候補を示し、書き込み再送、資源の取り込み・削除、pending解除は行いません。
- 既存CIは最低対応版に加えて最新alphaとnextを検出し、公開app-bootとの照合と、配布物を実DSHへ導入するHTTP/RPC/WSテストを実行します。

## 導入・更新

```sh
dsh plugin --profile web add -w 'github:Aero123421/dsh-cf#v0.1.0-alpha.7'
```

DSHを再起動し、ブラウザを一度再読み込みしてください。既存の設定・専用Tunnel/DNS/AccessのID・connector tokenは保持します。Cloudflareの管理用APIトークンはメモリ内のみのため、再起動後の設定変更では再入力します。

新規導入で確認したDSHは`0.2.1-rc.2`です。npmの`latest`は確認時点で`0.2.0-rc.2`のため、必要なDSH版を明示してください。
