# dsh-cf

自分のPCで動くDSHを、Cloudflare経由で外から使うためのプラグインです。

普段の操作は **公開URLを開く → 自分のメールなどでログイン → DSHを使う** だけです。同じURLをMac・スマートフォン・タブレットから使えます。ホストPCの電源とインターネット接続は必要です。

> 開発プレビューです。Cloudflareは通信を中継・復号します。DSHを使える人はPC上のファイルやコマンドも扱えるため、本人だけを許可する構成です。

## 用意するもの

- DSH `0.2.1-alpha.2` 以降の対応する `0.2` 開発版とNode.js `22.18` 以上
- Cloudflareで管理しているドメインと、初期設定済みのCloudflare One（Zero Trust）
- 公開用の未使用サブドメイン。ドメイン直下の1階層だけです。例：`dsh.example.com`（`a.b.example.com` のような2階層以上は、Cloudflareの無料証明書が対象外のため設定前に拒否します）
- ログインを許可する、自分のメールアドレス

**DB、Workers、ルーターのポート開放は不要です。** Touch ID・物理セキュリティキーの登録も、追加認証を使わなければ不要です。

## 初回だけ行うこと

### 1. プラグインを入れる

DSHを新規導入する場合は、確認済みの版とプラグイン導入用のpnpmを入れます。2026-10-19時点のnpm `latest`と`next`は`0.2.1-rc.2`で、このプラグインの対応範囲です。既に対応版とpnpmを使っている場合、最初のコマンドは不要です。

```sh
npm install -g @deepseek-ai/dsh@0.2.1-rc.2 pnpm@11.25.0
```

プラグインは公開タグを指定して導入します。

```sh
dsh plugin --profile web add -w 'github:Aero123421/dsh-cf#v0.1.0-alpha.9'
```

実行中のDSHを再起動し、**設定 → Cloudflare** を開きます。同じプロファイルのDSHを二重起動しないでください。

設定画面の表示言語はDSHの言語設定に従います。DSH本体が持つのは英語と中国語です。このプラグインは日本語の辞書も登録しますが、DSHの言語一覧に「日本語」を追加しません。日本語で表示するには、日本語を追加する言語パックのプラグインが必要です。言語パックがない場合は英語で表示します。

画面上に更新ボタンはありません。プラグインの一覧はサイドバーの Plugins です。入れ替えは、次のコマンドで新しい公開タグを指定します。DSH のプラグイン一覧に更新ボタンが出るのは、公式カタログから入れたプラグインだけです。

```sh
dsh plugin --profile web add -w 'github:Aero123421/dsh-cf#<tag>'
```

プラグイン自身に更新機能はありません。更新後はDSHを再起動し、ブラウザも一度再読み込みして新しい設定画面を読み込みます。プラグインを入れ替えても、保存済みの設定・接続トークン・Cloudflareの資源は削除されません。配布物のtarballとSHA256SUMSをリリースへ付ける手順は[リリースノート](docs/releases/v0.1.0-alpha.9.md)にあります。

設定画面の表示はDSH標準のUI部品を使います。入力途中の公開先・ホスト名・メールは、設定画面を閉じて開き直しても同じページの間は残ります（メモリー上だけで、保存はしません。APIトークンは残りません）。

設定の作成・変更は、DSHホストのlocalhost接続で行います。公開URL（Cloudflare経由）から開いた設定画面は読み取り専用の簡易状態だけで、アカウント一覧・資源ID・ポートなどは表示されず、操作もできません。別のPCから設定する場合は、SSHで転送します。

```sh
ssh -N -o ExitOnForwardFailure=yes -L 3080:127.0.0.1:3080 USER@HOST_PC
```

DSHが3080番ポートで動いている例です。SSHの認証を完了し、ターミナルを開いたまま、ホスト側のDSHが表示するログインURLのホスト部分を `http://127.0.0.1:3080/` に置き換えて開きます。`?token=...` は省略しません。この管理用URLは共有しないでください。

### 2. Cloudflareへの接続を許可する

[CloudflareのAPIトークン画面](https://dash.cloudflare.com/profile/api-tokens)でカスタムトークンを作り、プラグインの **1. Cloudflareに接続** のAPIトークン欄に入力し、**Cloudflareに接続** を押します。チャットやIssueには貼らないでください。

| 分類 | 権限 | アクセス |
|---|---|---|
| Account | Account Settings | Read |
| Account | Cloudflare Tunnel | Edit |
| Account | Access: Apps and Policies | Edit |
| Account | Access: Organizations, Identity Providers, and Groups | Read |
| Zone | Zone | Read |
| Zone | DNS | Edit |

対象アカウントと対象ドメインに限定します。Editはその権限グループの読み取りも含みます。組織の追加認証設定をプラグインから変更するときだけ、OrganizationsのEditも必要です。

管理用APIトークンはメモリ内だけに保持し、入力から1時間で失効します。通常の再接続や自動復旧には不要ですが、設定の変更・公開設定の削除・書き込み結果の復旧では、DSH再起動後や失効後に再入力します。画面には失効時刻を表示し、失効したトークンは破棄します。

### 3. 公開先を決めて接続する

- **Cloudflareアカウント・ドメイン**：自分のものを選択
- **ログイン方法**：メールコードなど、Cloudflareに登録済みの方法
- **公開ホスト名**：`dsh.example.com` など。選んだドメインの直下1階層だけ
- **本人のメール**：アクセスを許可するメールアドレス1つ

候補が1つだけのアカウント・ドメイン・ログイン方法は自動で選びます。メールアドレスは自分で確認して入力します。

接続ソフトが未導入なら、公式cloudflaredの取得を許可し、**接続する** を押します。プラグインが専用Tunnel、DNS、本人だけを許可するAccessアプリを作ります。

### 4. 公開URLを開く

状態がオンラインになったら、公開URLの **開く** を押し、本人のメールコードなどでログインします。そのままDSHが開きます。別の確認リンクや通信チェックの手動操作は不要です。ブラウザからのAPI・WebSocketの通信は、最初にトップページを開いていなくても、本人確認後に使えます。

自動接続がオフのまま、または一時停止したままDSHを再起動した場合は、状態の欄の **再開** を押します。保存済みの設定で再接続するだけで、APIトークンは要りません。

正常な通信を確認した後、必要なら **DSH起動時に自動で公開** をオンにします（通信を確認するまでは選べません）。次回からは公開URLをブックマークして使えます。日常利用にSSH転送や管理用APIトークンは不要です。

設定済みのアカウント・ドメイン・ホスト名・本人メール・ログイン方法は、Cloudflareに専用の資源を作った後は編集できません。変更する場合は、認可したローカル設定画面で **公開設定を削除…** を行ってから設定し直します（確認画面でホスト名を入力します。完了すると画面に表示します。DSHの信頼するホストの設定を自動で戻せなかったときは、そのホスト名を表示するので、DSHの設定から手動で外します）。最初の作成が拒否されて資源がまだ1つもない場合は、入力を直して再実行できます。追加認証の有無は、**追加認証（WebAuthn）** のスイッチで変更できます（下記）。

## 状態の見方

設定画面の状態は次のどれかです。

| 状態 | 意味 |
|---|---|
| オンライン（`online`） | ゲートが待ち受け、cloudflaredがCloudflareに接続済みです。ブラウザを開いているかは関係しません。タブを閉じても、15分のWebSocket上限で切れても、DSHを再起動しても、これだけでは変わりません。 |
| 再接続中（`reconnecting`） | cloudflaredが切断中か、自動復旧の次の試行を待っています。待機中は再試行時刻を表示します。 |
| 接続処理中（`starting`） / 停止処理中（`stopping`） | 接続または停止の処理中です。 |
| 一時停止中（`paused`） | 一時停止を押して止めた状態です。DSHを再起動しても自動では再開しません。 |
| 未接続（`offline`） | 設定済みで動いていません。自動接続がオフのまま起動した場合や、取消しの後です。 |
| エラー（`error`） | 失敗して止まり、自動の再試行もありません。表示された原因を直してから再開します。 |
| 未設定（`unconfigured`） | まだ公開設定がありません。 |

確認済み（`verified`）は別の情報です。ログインした本人のHTTP・API・WebSocketの実通信と、未認証アクセスの拒否を観測したときにだけ付き、最終確認時刻と一緒に保存します。通信が一時的に途切れても外れません。

DSHがエラーや401を返した場合、状態はオンラインのまま警告を出し、次に成功したリクエストで消えます。DSHが401を返すときは、プラグインが新しいセッションを自動で取り直すので、ブラウザの再読み込みで足ります。

## 一時停止・取消し・自動復旧

- **一時停止**：公開を止め、停止したことを保存します。自動接続の設定はそのままです。DSHを再起動しても、**再開** か **接続する** を押すまで接続しません。DSH自体の終了・プラグインの停止・プロファイル所有権の喪失では、一時停止を保存しません。
- **取消し**：実行中の処理と管理リクエストだけを中断します。アカウント一覧の取得などを取り消しても、動いている公開は止まりません。公開を作り直している最中の処理を取り消した場合は、作りかけの公開を閉じて停止中になります。
- **自動復旧**：DSHの起動時（自動接続がオンで一時停止していないとき）と、公開中にcloudflaredが予期せず終了したとき（一時停止していないとき）に、保存済みの接続トークンで再接続します。Cloudflareへの書き込みはしません。起動時の自動接続は、前回の設定確認が済んでいて、ホスト確認待ちや書き込み結果の不明がない場合だけ行います。失敗が一時的な原因なら、5秒・15秒・30秒・60秒・120秒の後、成功するか操作されるまで300秒ごとに再試行します。保存済みゲートポートが使用中のとき（`GATE_PORT_BUSY`）は、その待ちではなく約1秒ごとに再試行します。一時停止・接続・再開・削除・取消しの操作と、DSHの終了で再試行は止まります。
  - 再試行する失敗：cloudflaredの起動・登録の失敗や終了、外部からの未認証確認で通信できない、DSHの待受や応答の失敗、保存済みのローカルポートが使用中。
  - 再試行しない失敗：未認証のURLが成功を返した（`UNPROTECTED`）、設定の未完了、ホスト確認待ち、書き込み結果の不明、プロファイルのロック、状態ファイルの異常、cloudflaredの実行ファイルの不備、Cloudflare側のリソースの不一致。止まったまま、原因を表示します。
  - 設定を保存して接続する操作（認可が必要な接続）が一時的な原因で失敗した場合は、自動では再試行しません。画面の指示に従って再度実行します。
- **ローカルポートの使用中**：再接続（トークンのみ）では保存済みのポートを変えられません。そのポートを cloudflared より先に確保し、確保できないときは cloudflared を起動せず、約1秒ごとに再試行します。Cloudflareを認可して接続し直すと、新しいポートへ移し、専用Tunnelの転送先を更新します。

## ログインを覚える期間

DSH用のAccessセッションは **1週間（168時間）** です。通常はブラウザのCookieにログイン状態を保持します。Cookieの削除、シークレットウィンドウ、セッションの失効などでは再ログインが必要です。

既に発行済みのCookieの期限は後から延長されません。期間変更後に新しく発行されるセッションから適用されます。ポリシー側に別の期間が設定されている場合は自動で上書きせず停止します。

## Touch IDなども使いたい場合だけ

新しく設定するときは **3. 接続 → 詳細設定** の **追加認証（WebAuthn）** をオンにします。設定済みの場合は、状態の下の **追加認証（WebAuthn）** スイッチを切り替えます。この場合はAccessへのログインに加え、登録したTouch IDやセキュリティキーで確認します。

認証器の登録にはCloudflareのApp Launcherが必要です。未設定なら [公式の有効化手順](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/app-launcher/)で本人のメールだけを許可し、App Launcherの **Account → MFA devices** で登録してください。

既存のWebAuthn必須設定は、更新だけでは解除しません。スイッチを切り替えると確認画面が開き、Accessアプリを更新して接続し直します。このとき自動公開はオフになり、外部からの通信確認がやり直しになります。管理用のAPIトークンが必要です。

追加認証を使わない設定（Accessのログインだけ）では、アプリを `mfa_config` なしで作成し、WebAuthnから切り替えるときは `mfa_disabled: true` を送ります。読み戻しでは `mfa_config` の欠落・null・`mfa_disabled: true` のどれも受け付けます。組織全体の追加認証の設定は、プラグインから読み取りも上書きもしません。Cloudflareが `mfa_config` のないアプリにその設定をどう適用するか、およびこの読み戻しの扱いは、実際のCloudflareアカウントでの確認が済んでいません。

## 開けないとき

| 表示・症状 | 確認すること |
|---|---|
| `DNS_PROBE_FINISHED_NXDOMAIN` | 開いている端末のDNSが公開ホスト名を見つけられていません。設定画面のURLに誤字がないか確認し、別回線や別のDNSで試します。ルーターが古い応答を返す場合もあります。 |
| `127.0.0.1` で接続拒否 | 別PCから管理している場合はSSH転送が切れています。SSHの認証完了を確認し、ターミナルを開いたままにします。 |
| `dsh web authentication required` | 管理用URLの `?token=...` が必要です。再起動後は新しいURLで開きます。 |
| 「このアカウントは許可されていません」 | 許可していないメールでログインしています。表示のログアウトリンクで出てから、設定した本人のメールでログインし直します。 |
| 「ログインを確認できませんでした」（503） | このPCがCloudflareのログイン確認用の鍵を取得できていません。ログインし直す必要はありません。回線を確認して少し待ちます。直前に取得できた鍵は、最後の成功から24時間まで、新しい鍵の取得に失敗している間だけ使います。 |
| Accessでログインできない | 許可したメールとログインに使ったメールが同じか確認します。追加認証をオンにした場合は認証器の登録も確認します。 |
| 接続済みなのにDSHが応答しない | ホストPCでDSHが起動しているか確認します。状態にDSHの応答失敗の警告が出ます。DSHが戻れば、次の成功で自動的に消えます。 |
| 状態が「エラー」でプロファイルのロック・状態ファイルの異常 | 設定画面は開けます。別のDSHがこのプロファイルを使っていないか確認します。開始時刻を確認できないときもロックになり、以前の cloudflared は止めず、新しいものも起動しません。停止シグナルのあと、終了を確認できないままプロセスが残っているときもロックになり、新しいものは起動しません。止めたあともプロセスが残っているときもロックになり、新しいものは起動しません。状態ファイルの異常では、`.dsh-cf/state.json` を控えてから直し、DSHを再読み込みします。プラグインは状態を書き換えません。 |
| ホスト確認が出る | コピーしたプロファイルを別のPCで開いたときに出ます。同じTunnelを2台で動かさないことを確認して承認します。承認すると、自動接続がオンなら自動で再開します。 |
| 変更結果が不明と表示される | 何度も保存し直さず、[書き込み結果の復旧手順](docs/reference.md#不明な書き込みの復旧)を確認してください。画面から、結果を確認して記録を整理する3つの操作を実行できます。 |
